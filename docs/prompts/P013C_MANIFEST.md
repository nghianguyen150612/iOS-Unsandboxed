# P013C implementation manifest

P013C composes P010 descriptor identity, P011 policy scope, P012 C17 descriptor preview and revalidation, P013 RustCrypto Ed25519 verification, and P013B trust transaction/generation checks in a read-only v2 authenticated preview. The command is `iu provenance plan MANIFEST ARTIFACT`.

The production provider opens the artifact once with no-follow flags, binds Rust and C17 observations to that descriptor, parses the canonical manifest, loads the production publisher trust store through hardened descriptor traversal, checks revocation and generation/digest state, verifies Ed25519 internally, and revalidates artifact, manifest, trust snapshot, and P011/P012 policy state. P013D-1 adds a separate typed attestation entry in the same composite provider. It binds DSSE/in-toto/SLSA subject SHA-256 to the descriptor snapshot and applies an independent versioned builder provider; it does not consult publisher keys as builder roots. C summary ABI v2 is pointer-free and 3376 bytes. P012 ABI v1 remains unchanged.

Publisher authentication does not establish source/build origin or override protected-origin policy. P013D-1 supports DSSE Protocol v1.0.2, in-toto Statement v1, and SLSA Provenance v1.0, but production has no independent builder root, so build origin remains `BUILD_ORIGIN_UNVERIFIED`. Protected origin is `UNKNOWN`, runtime is `UNVERIFIED`, the launch boundary is `NOT IMPLEMENTED`, execution activation is disabled, and operational authorization is always false. The operation creates no authorization token and does not contact the daemon.

See `docs/architecture/provenance-launch-integration.md`, `docs/architecture/authenticated-binding-v2.md`, `docs/architecture/independent-build-attestation.md`, `docs/architecture/builder-trust-contract.md`, and `docs/validation/P013D1_ATTESTATION_GATES.md`. Overall P013 remains partial pending production builder trust and protected-origin evidence. Physical-device validation remains NOT RUN.
