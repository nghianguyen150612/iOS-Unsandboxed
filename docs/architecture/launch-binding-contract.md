# Identity-bound launch intent (P012)

`iu_launch_binding.h` defines ABI v1. A request supplies an operation, requested pathname and optional bounded evidence bytes. The result records that pathname, P010 canonical path and identity (device, inode, size, owner, group, mode, link count, nanosecond mtime and ctime, digest and Mach-O classification), P011 scope device/inode, store state, P003 outcome, a clearly hypothetical P003 path classification, P009 capabilities, evidence result and missing prerequisites. It is a pointer-free observation, not a bearer token or a launch permit. Operational authorization is always zero; the launch boundary is not implemented.

The preview borrows the descriptor and does not change its offset or close it. It checks regular, single-link bounded objects; P010 opens the path without symlink traversal and records identity; P009 hashes and parses the caller's descriptor; the two observations and complete metadata must match. P010 reopens and revalidates the pathname. `revalidate_fd` compares the borrowed descriptor, path identity, metadata and digest, the current caller-supplied evidence bytes, and the currently readable policy store identity, content digest and scope. It distinguishes same open object, path replacement, modified object, unverified descriptor identity, stale evidence and stale policy. The evidence and policy are snapshots, not continuous monitors. Invalid ABI, operation, sizes and enum values are rejected. Unreadable policy is unverified; a valid v1 preview-only store and current scope device/inode are required to report a scope match.

The descriptor represents an object observed now, not a future process. No P012 mechanism binds `execve(path)` to it; closing it or reusing this result cannot guarantee anything about a later launch. An exact-object launch mechanism and atomic rechecking of origin, policy and identity remain future work. Revalidation is a read-only check and cannot grant permission.
