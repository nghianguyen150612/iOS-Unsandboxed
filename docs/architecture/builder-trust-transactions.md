# Builder trust transaction metadata

The C17 ABI v1 uses a fixed 312-byte structure guarded by `_Static_assert`; its parser, encoder, validator, and explicit return codes are pure in-memory functions. The Rust parser accepts the same bounded ASCII/LF journal in `transaction.v1` (maximum 1 KiB), with ordered fields: header `ios-unsandboxed-builder-transaction`, `schema_version=1`, `operation` (`roots`, `policies`, or `combined`), old and new root generations and SHA-256 digests, old and new policy generations and SHA-256 digests, fixed `stage_roots=roots.stage.v1`, `stage_policies=policies.stage.v1`, and `phase=prepared`. The canonical field order is shown by `tests/builder-trust/valid-transaction.v1`; shared adversarial vectors are in `transaction-vectors.json`. Old generation and digest are both `none` for an absent store. An unchanged store retains both generation and digest; a changed present store increments its generation by one and changes its digest; an absent store starts at generation one. Overflow and arbitrary stage names are rejected. The `phase` field is syntactic metadata only and never establishes that a write committed.

The read-only `state.v1` marker (maximum 512 bytes) uses the ordered ASCII lines `ios-unsandboxed-builder-state`, `schema_version=1`, `root_generation`, `root_sha256`, `policy_generation`, and `policy_sha256`. Without a transaction, it must match both loaded stores. With a journal, the classifier compares it to the actual old or new pair. An absent marker is reported as legacy unanchored history outside a transaction. Neither marker nor journal is independently rollback-resistant.

P013D-2B-2 constructs a compatible `transaction.v1` byte image and next `state.v1` marker only in memory. A changed roots-only or policies-only plan preserves the other existing generation/digest; first materialization starts that store at generation 1. First enrollment from two absent stores produces a combined pair. Rust validates every proposed image with the existing parsers; `mutation-vectors.json` is also accepted and byte-for-byte re-encoded by the C17 codec. Planning refuses any observed journal or orphan stage. It does not create stages, journal, marker, or stores and does not perform crash recovery.

## Read-only crash-state classification

The reader opens the two canonical stores, both fixed stage names, the journal, and the marker relative to the held directory descriptor. Every file receives the same root ownership, mode `0600`, regular-file, single-link, bounded-read, before/after identity, and reopen checks as the canonical stores. The directory chain is revalidated before the classification is returned. Unknown entries, symlinks, hard links, unsafe modes, malformed data, and replacement races fail closed.

The classifier compares parsed store generations and SHA-256 digests with the journal's old/new identities and the stage file contents. It does not use `phase` to infer progress. It reports `NO_TRANSACTION`, `PREPARED_OLD_PAIR`, `FIRST_STORE_REPLACED`, `SECOND_STORE_REPLACED`, `BOTH_STORES_REPLACED`, `COMMITTED_PAIR_MARKER_PENDING`, `COMPLETE_COMMIT`, `RECOVERY_REQUIRED`, `CONFLICTING_STATE`, `CORRUPT_TRANSACTION`, `UNSAFE_TRANSACTION_ARTIFACT`, or `UNKNOWN_STATE`. A stage without a journal is `RECOVERY_REQUIRED`. Invalid or modified stages and store/marker pairs that match no expected identity are conflicting.

Every journal or stage artifact blocks signer and policy authority, including `COMPLETE_COMMIT`: this code only classifies observed state and does not remove transaction metadata. It neither repairs nor deletes anything. Production commit and recovery writes are not implemented, and a classifier is not crash recovery. Local generations and the marker do not provide independent rollback protection. C17 and Rust use a shared set of 24 deterministic canonical and adversarial vectors; Rust unit tests also cover each observable pair state.
