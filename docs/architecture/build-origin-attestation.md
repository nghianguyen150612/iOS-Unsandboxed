# Build-origin evidence boundary

P013 manifests carry an artifact identity plus claimed build artifact ID, source repository, source revision, workflow, builder, and publisher. These fields are included in the Ed25519 signed bytes. The signature establishes that a trusted publisher made those claims; it does not independently establish that the binary was built from that source or workflow.

P013D-1 implements a bounded offline verifier for DSSE Protocol v1.0.2, in-toto Statement v1, and the SLSA Provenance v1.0 predicate. It checks signatures with `ed25519-dalek`, binds the subject to the P013C opened descriptor, and exposes a versioned independent builder-provider interface. Production has no independently authenticated signer or builder root configured, so every production report still says `BUILD_ORIGIN_UNVERIFIED`, even when the document is well formed or a synthetic test fixture passes. There is no transparency-log integration or reproducible-build verifier. The pinned Amethyst source revision is not evidence of the installed Amethyst binary's build.

Production builder trust still needs an authenticated root, signer identity mapping, builder policy, lifecycle/revocation, and rollback protection. The current verifier binds the subject digest to the inspected artifact and can check source/build parameters against such a policy when configured; P013D-1 does not supply that production trust. Source claims do not constitute independently verified source identity, and no attestation satisfies protected-origin policy without a separate authoritative Apple artifact classifier.
