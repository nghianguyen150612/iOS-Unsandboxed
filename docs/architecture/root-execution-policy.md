# Root-controlled execution policy (P011)

P011 stores administrator-selected scopes for **read-only previews**. It does not activate execution, prepare a binary, modify a process, create a launch token, or expose a policy mutation through IPC. `install-state` remains the unchanged schema-v1 `execution_activation=disabled` record. An absent policy is a valid empty configuration. The daemon and service lifecycle do not load policy as authorization.

The manager provides `policy help`, `status`, `plan`, `list`, `preview PATH`, `add-directory PATH`, `remove-directory PATH`, and `reset`. Mutations are plans unless both `--apply --confirm` are present. A mutation requires effective UID 0 on production, the P007 iPad4,4/iOS 12.5.7 and rootful layout checks, a verified P007 manifest and disabled state, and the shared installer transaction lock. The manifest verifies installed manager and helper files and ownership; it is not package provenance. No `--force` exists. Fixture mode is compiled only for the test helper, uses an explicit `--test-root`, and simulates owner IDs.

Enrollment is restricted to canonical directories strictly below `/opt/ios-unsandboxed-scopes/`. The administrator must create this tree. A newly enrolled directory must be empty, so a directory already containing any executable, including an Apple service, is rejected. Files may be added afterward; their provenance is not established by enrollment. Each component is opened relative to the root descriptor without following symlinks and must be a directory owned by root:wheel (fixture UID/GID in tests), with owner read/search and no group/world write. Dot components, whitespace, non-ASCII, overlapping scopes, and more than eight entries are rejected. Device and inode are recorded and checked on every preview and update. A scope is not a list of approved executables: target and parent checks are repeated per preview. The narrow namespace excludes the system, Amethyst, and project-owned trees, but it **cannot identify** an Apple system executable copied into the tree after enrollment. All artifacts have unverified provenance in P011, regardless of a directory-scope match. For an otherwise structurally eligible target, preview therefore reports `ARTIFACT_PROVENANCE_UNVERIFIED` instead of `HYPOTHETICALLY_ELIGIBLE`; the internal P003 simulated result is strictly a directory-match diagnostic. No copied executable is ever eligible for launch solely because the scope was registered. This deliberately blocks arbitrary copied binaries without claiming to detect Apple origin. Future artifact-specific provenance verification requires a separately reviewed design. Registration does not recursively inspect or modify contents.

Read-only commands use the caller's filesystem access and report unsafe or inaccessible metadata rather than granting access. `preview` checks the target's parent chain, obtains the P010 descriptor-backed identity and Mach-O facts, revalidates the target, and compares P003's disabled operational decision with an explicitly simulated scope decision. The simulation assumes verified compatibility solely to determine hypothetical scope eligibility. P009 evidence and all runtime prerequisites remain separate, and `operational_authorization` is always false.
