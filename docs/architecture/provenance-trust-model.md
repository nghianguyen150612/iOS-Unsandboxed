# Provenance trust model

A SHA-256 digest identifies content relative to a reference; it does not authenticate that reference or establish where the bytes came from. Directory enrollment, ownership, restrictive mode, architecture, CodeDirectory parsing, and an administrator's label express local facts or intent. None authenticates a publisher or demonstrates that an executable is not a copied Apple system binary. A valid publisher signature alone would also not establish an adequate non-protected origin policy.

P013's Rust verifier uses Ed25519 via `ed25519-dalek` and a canonical signed manifest. That store authenticates publisher claims; it is not builder authority. P013C's `iu provenance plan MANIFEST ARTIFACT` composes publisher verification with the production root-owned publisher store and P012's borrowed-descriptor preview. P013D adds `iu provenance attestation verify ATTESTATION ARTIFACT`, which checks a DSSE-signed in-toto/SLSA statement against the same P013C opened-descriptor identity and consults a separate versioned builder-verification provider. P013D-2A adds read-only canonical builder roots and exact policies; the builder provider never imports publisher trust. Locally installed roots do not establish an independent CI identity, so production keeps `BUILD_ORIGIN_UNVERIFIED`. Host fixtures exercise real signatures with isolated synthetic roots. Neither path accepts caller-supplied verification booleans or uses the legacy C v1 provenance result as cryptographic proof.

The local publisher store and generation marker support key lifecycle and detect local inconsistencies while the marker remains present, but they are not an independent monotonic anchor; `ROLLBACK_PROTECTION_UNVERIFIED` remains explicit. Publisher authentication confirms only that an active publisher key signed a claim matching the exact opened artifact. A builder attestation can report origin verified only when its signer, builder identity, parameters, source revision, and descriptor-bound subject all pass an independently configured builder policy. That production policy is not available yet, so build origin remains `ORIGIN_UNVERIFIED`. A source revision claim is not independently verified source identity, and no reproducible-build evidence is produced. Protected origin remains `UNKNOWN`, and P003 remains disabled. A reviewed protected-artifact classifier with defensible completeness assumptions is still required. Do not infer non-Apple origin from failure to match a small database. No attestation authorizes launch.
