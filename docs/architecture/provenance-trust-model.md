# Provenance trust model

A SHA-256 digest identifies content relative to a reference; it does not authenticate that reference or establish where the bytes came from. Directory enrollment, ownership, restrictive mode, architecture, CodeDirectory parsing, and an administrator's label express local facts or intent. None authenticates a publisher or demonstrates that an executable is not a copied Apple system binary. A valid publisher signature alone would also not establish an adequate non-protected origin policy.

Production P012 has no authoritative trust anchors and no supported signature algorithm. Its typed trust boundary is intentionally unavailable. Only a test build links the deterministic fixture provider, which models authenticated, rejected, protected and unprotected assertions against a single synthetic object. It is not a cryptographic verifier or an Apple catalog; the production binary has no environment variable or runtime selector to enable it. Unknown publishers, anchors, source, catalog coverage, and origin fail closed. A local root declaration is not publisher authentication.

A future provider must specify an independently reviewed trust root, supported algorithm and key lifecycle (including revocation and rotation), canonical signed bytes, exact artifact binding, and failure handling. A distinct reviewed origin policy must explain the protected-artifact coverage and completeness assumptions before it can label an artifact operationally eligible. Do not infer non-Apple origin from failure to match a small database. Even authenticated evidence does not override disabled P003 policy or authorize launch.
