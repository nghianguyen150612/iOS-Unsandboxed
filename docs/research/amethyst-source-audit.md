## Call graph and component responsibilities

Amethyst's jailbreak handoff extracts its basebins, preloads them, and injects the launchd hook into PID 1 through jbutil --kickstart. The injector path is jailbreak_handoff → inject_launchd_hook → run_jbutil("--kickstart") → inject_dylib(1, "/amethyst/launchd_hook.dylib"). See [handoff.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/Amethyst/Amethyst/jailbreak/handoff.c#L258-L303), [jbutil/main.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/jbutil/src/main.c#L39-L89), and [injector.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/jbutil/src/injector.c#L252-L264). The handoff preloads /amethyst/launchd_hook.dylib and /usr/lib/base_hook.dylib; the Amethyst package installs those files at those Amethyst-owned paths, not in /usr/local/lib ([handoff.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/Amethyst/Amethyst/jailbreak/handoff.c#L170-L265), [basebins/Makefile](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/Makefile#L49-L66)).

The launchd-hook constructor reads kernel addresses and version information from Amethyst's handoff plist, identifies the SoC, initializes trust-cache state, installs its XPC server hooks, and hooks posix_spawn. It obtains host special port 4 as tfp0; A7/A8 use the 4 KiB page case, while the code marks PPL only for A12 and later SoCs. The iOS 12 offset table is selected by major version, with a separate special case for 12.0. See [launchd_hook/main.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/main.c#L13-L138) and [constructor](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/main.c#L170-L223). init_server() and init_loader() return status, but the constructor does not check either return value.

When launchd calls posix_spawn, the launchd hook filters selected paths and process types, calls process_binary(path) before spawning, and adds /usr/lib/base_hook.dylib to the child's environment. process_binary selects signing or trust-cache work only after extracting a signature from an executable slice. The status from process_binary(path) is ignored by the spawn hook. See [launchd_hook/loader.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/loader.c#L42-L68) and [spawn handler](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/loader.c#L70-L144).

The injected base hook runs its constructor in processes where dyld loaded it. It initializes Amethyst metadata, restores a default PATH if absent, handles setuid/setgid metadata, and calls jbserver_unsandbox(getpid(), JBSERVER_UNSANDBOX_AUTO). It then hooks execve and posix_spawn. Those hooks resolve the target path and call jbserver_process_binary before executing/spawning it; the returned error is ignored. See [base_hook/main.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/base_hook/src/main.c#L32-L81), [base_hook/loader.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/base_hook/src/loader.c#L109-L195), and [basebin_jbserver.c](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/common/src/basebin_jbserver.c#L229-L253).

The principal source symbols are macho_load, macho_get_signature, macho_sign_binary, macho_should_sign, sign_binary, trustcache_init, trustcache_add_hash, trustcache_add_binary, trustcache_lock_add_hash, process_binary, jbserver_process_binary, jbserver_sign_binary, jbserver_trustcache, jbserver_unsandbox, init_server, init_loader, hook_function, execve_hook, and posix_spawn_hook. Relevant implementation-specific types include macho_ctx_t, macho_slice_t, macho_signature_t, CS_CodeDirectory, CS_SuperBlob, fsignatures_t, trustcache_info_t, kinfo_t, jbserver_cmd_t, jbserver_err_t, jbserver_unsandbox_type_t, jbserver_base_msg_t, and the private XPC dictionaries. The functions in these hook targets are not exported as a stable SDK; the C declarations and call sites are inside a hidden-visibility build.

## Unsandbox mechanism

The base-hook constructor acts on its own PID, using jbserver_unsandbox(getpid(), JBSERVER_UNSANDBOX_AUTO), during dyld initialization after process creation and before normal program entry. This is a per-process operation in Amethyst's source; it does not explicitly install a process-tree policy. Whether the kernel carries the sandbox label into a forked child is outside the inspected source and requires device investigation. The server can also accept an explicit PID, resolve that process, and zero its sandbox MAC label slot. Its init_process operation can separately alter code-signing flags, platform task state, and optionally the sandbox slot. See [base-hook call site](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/base_hook/src/main.c#L63-L81), [client policy](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/common/src/basebin_jbserver.c#L113-L209), and [server process mutation](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/jbserver.c#L54-L116).

AUTO selects NONE for selected plugin/XPC path substrings, EXT for selected Apple service executables, and FULL for selected application paths, executable paths under /usr or /Library, root effective UID/GID, or entitlements that indicate no sandbox/container or broad root filesystem access. For a PID different from the caller, AUTO selects FULL. EXT consumes up to six sandbox-extension tokens from the current basebin metadata; FULL sends the server an UNSANDBOX request. The server sets the target's sandbox label slot to zero. The server's explicit-PID request path does not show a caller authorization or product opt-in check. Amethyst's base-hook constructor applies AUTO to every eligible injected process; that policy is broader than iOS-Unsandboxed's required target opt-in.

FULL therefore needs the jailbreak server's kernel process/credential lookup and kernel write capability from Amethyst. EXT depends on tokens supplied through the Amethyst/dyld handoff. This is reuse of Amethyst's installed kernel capability, not an independent iOS-Unsandboxed exploit. It can alter only the selected process state when the server resolves a PID, but the current automatic caller applies policy to many unrelated injected processes. jbserver_unsandbox, set_mac_slot, and kernel write helpers do not provide end-to-end readback/error reporting for each mutation; some error paths can report success after a void helper returned early. The base-hook caller ignores the returned error.

The safe reuse shape is a reviewed policy check that opts a target in, followed by an operation on that target PID only, after the process exists and before its main entry. The current AUTO policy must not be reused as the product's eligibility decision. Disabling the project feature can stop future operations, but the source has no per-process sandbox restoration operation. Any lifecycle or rollback guarantee must be validated on the device.

## Build configuration and target fit

The basebin Makefiles compile the hooks with Apple's iPhoneOS SDK, -mios-version-min=12.0, ARM64 and ARM64e slices, warnings-as-errors, hidden symbol visibility, and strip -x; they run ldid -S on the resulting dylibs. The base_hook and launchd_hook targets are dynamic libraries. launchd_hook links CoreFoundation and other iOS frameworks. See [base_hook/Makefile](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/base_hook/Makefile#L1-L15), [launchd_hook/Makefile](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/Makefile#L1-L19), and [SoC/version selection](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/basebins/launchd_hook/src/main.c#L25-L138). The Xcode application target has an iOS 15.5 deployment target; the basebin hook targets are separately configured for iOS 12.0. P002 conclusions concern the basebins, not the Amethyst UI app ([project settings](https://github.com/staturnzz/amethyst/blob/61ce86d7d3f00e5395f4d42bebda0e5dce04946a/Amethyst/Amethyst.xcodeproj/project.pbxproj#L380-L515)).

This configuration is source-level evidence that upstream builds an ARM64 hook for iOS 12.0 and contains A7/iOS 12 code paths. It does not prove the pinned build initializes on the A1489 running iOS 12.5.7, nor that any P002 integration or unsigned binary works there.

## Evidence limits

Source confirms the named functions and call sites only at the pinned revision. It does not establish their runtime behavior on the physical target, current installed Amethyst version, exact iOS 12.5.7 kernel behavior, or ABI stability. Amethyst's hooks use private XPC and kernel interfaces. No Amethyst build or device execution was performed as part of this source inspection.
